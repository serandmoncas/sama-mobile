# Spec — Mapa base con MapLibre

**Fecha:** 2026-07-28
**Estado:** Aprobada
**Ticket del backlog:** E3-01

## Historia de usuario

**Como** ciudadano
**quiero** ver un mapa de Antioquia en la app, con gestos estándar y mi ubicación si la comparto
**para** orientarme sobre el territorio, como base para ver estaciones más adelante (E3-02)

## Conversación

- **Dependencia nativa: decisión aceptada.** `@maplibre/maplibre-react-native` no funciona en Expo Go — requiere una build de desarrollo nativa (`npx expo run:ios`/`run:android`), la misma vía que ya se usó y verificó funcionando en un iPhone físico en esta sesión. El usuario confirmó proceder sabiendo esto. El resto de la app sigue funcionando en Expo Go sin cambios; solo el tab "Mapa" pasa a necesitar la build nativa para verse.
- **Fuente de tiles: OpenFreeMap.** Se investigó la instalación real de la librería (documentación oficial de MapLibre React Native) y se confirmó: paquete `@maplibre/maplibre-react-native`, requiere `expo install` + plugin de configuración en `app.json`, compatible con React Native ≥0.80 y New Architecture (el proyecto ya cumple ambos con RN 0.86). Se eligió OpenFreeMap (`tiles.openfreemap.org`, estilo "liberty") como fuente de tiles porque es gratuita, no requiere API key ni cuenta, y está basada en datos reales de OpenStreetMap — evita fabricar o pagar por datos, y no añade fricción para correr el proyecto.
- **Ubicación: botón en el mapa, no en onboarding.** El permiso de ubicación se pide solo cuando el usuario toca un botón "Mi ubicación" en el mapa — no se agrega como paso nuevo al onboarding ya shippeado. Si el usuario niega el permiso, no pasa nada (sin alertas ni bloqueos), consistente con que es opt-in.
- **Alcance: solo el mapa base.** Esta spec cubre únicamente el mapa en sí (tiles, cámara centrada en Antioquia, gestos, botón de ubicación). La capa de estaciones con clustering (E3-02), el detalle de estación (E3-03), y las tarjetas "Mis territorios" en Inicio con datos reales (E3-04) son tickets aparte que dependen de datos que no existen todavía (E0-02/E2).
- **Testing: el mapa nativo se mockea.** MapLibre renderiza vistas nativas que no se pueden ejecutar de verdad en Jest. Las pruebas cubren la lógica propia de la pantalla (el botón de ubicación, su accesibilidad, el pedido de permiso) con el componente de mapa mockeado — no prueban gestos ni renderizado interno de MapLibre, que son responsabilidad de la librería.
- **Limitación conocida: rendimiento en gama baja no verificado.** El criterio de aceptación original del backlog pide probar el mapa en un dispositivo Android de referencia ≤2GB RAM. Ese dispositivo no existe en este entorno de desarrollo — se declara explícitamente como no verificado en vez de simular una prueba que no se hizo. La verificación real de este ciclo es funcional (compila, corre, no crashea) en los dispositivos disponibles (simulador iOS, iPhone físico).

## Criterios de aceptación

- [ ] CA1: el tab "Mapa" muestra un mapa real (no el placeholder actual) usando `@maplibre/maplibre-react-native`, con el estilo de OpenFreeMap.
- [ ] CA2: la cámara inicial del mapa está centrada en Antioquia, con un nivel de zoom que muestra la mayoría del departamento.
- [ ] CA3: el mapa responde a los gestos estándar de la librería (pan, pinch-zoom) sin configuración adicional que los deshabilite.
- [ ] CA4: hay un botón "Mi ubicación" visible sobre el mapa, con `accessibilityRole="button"`, un `accessibilityLabel` descriptivo, y un área tocable ≥44px.
- [ ] CA5: al tocar el botón, se pide el permiso de ubicación en primer plano (`expo-location`); si se concede, se muestra la ubicación del usuario en el mapa.
- [ ] CA6: si el permiso se niega, la app no crashea ni muestra ninguna alerta bloqueante — simplemente no se muestra la ubicación.
- [ ] CA7: el resto de la app (todas las demás pantallas) sigue funcionando igual que antes; no se rompe ningún flujo existente.

## Restricciones

- Dependencia nueva permitida explícitamente en este ciclo: `@maplibre/maplibre-react-native` y `expo-location` (con su plugin de configuración en `app.json`).
- No usar ninguna fuente de tiles que requiera API key o cuenta de pago.
- Copy visible en español; identificadores de código en inglés.
- TypeScript estricto; sin `any`.
- No tocar `app/_layout.tsx`, `app/alerta/[id].tsx`, ni ninguna otra pantalla fuera de `app/(tabs)/mapa.tsx`.
- No modificar `constants/Colors.ts` ni `constants/AlertColors.ts`.
- No agregar el permiso de ubicación al flujo de onboarding.

## No-objetivos

- Capa de estaciones, clustering, íconos por tipo/estado (E3-02).
- Detalle de estación con gráfica (E3-03).
- Tarjetas "Mis territorios" con datos reales de alerta en Inicio (E3-04) — ya existe una versión con `alertLevel="verde"` fijo desde el onboarding, eso no cambia aquí.
- Filtros por tipo de estación o cuenca (depende de E3-02).
- Verificación real de rendimiento en un dispositivo Android de gama baja (no hay uno disponible en este entorno).

## Verificación

Compila/typecheck → lint → unitarias (Jest + RNTL: componente de mapa mockeado, botón de ubicación con su accesibilidad y minHeight, pedido de permiso mockeado con `expo-location`, comportamiento cuando se niega el permiso) → ejecución real (build de desarrollo nativa en simulador iOS y, si es posible, en el iPhone físico ya configurado en esta sesión — verificación visual del mapa, la cámara centrada en Antioquia, y el botón de ubicación). No se verifica rendimiento en Android de gama baja (limitación de entorno, declarada arriba). Feature de tamaño mediano con una dependencia nativa nueva — spec con historia + criterios de aceptación es suficiente.
